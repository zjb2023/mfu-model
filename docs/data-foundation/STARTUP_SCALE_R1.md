256卡三轮均出现约1.1秒现象，非单iter偶发；32卡同规模也从1.175到28.969ms，说明rank数本身不是唯一解释变量。两种规模来自不同日期采集、不同层数、运行环境，不能用两个规模样本拟合因果增长公式。

带宽解释不足：按30GB/s，256卡ring每rank24480字节约0.000816ms，完全不是1秒量级。全局group扩大可能提高等最晚rank就绪的成本、增加算法阶段或放大运行时进度问题；其中哪项主导仍未确认。236B timers.py的全局FP32计时值汇总与张量形状吻合，仍无调用栈证明。未校准跨机时钟，不从各rank绝对时间推断最后到齐者。

建模建议：启动=本地准备＋全局统计/同步有效项＋首F启动，不与RS/AG大消息带宽项混用。保留规模和采集运行条件为输入标签；暂不将目标约1.1秒回填为独立预测参数，不按world size乘以源时长。
