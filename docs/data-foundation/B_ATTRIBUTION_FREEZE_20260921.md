# 32→256 中间B误差归因冻结 · 2026-09-21

## 固化结论

- 原1F1B预测21653.357840ms，目标iter60实测20396.013187ms，高估1257.344653ms（6.164659%）。
- 替换全部中间PP1–14的B实测成本后，高估减少1104.671894ms，解释原高估约87.86%。这是oracle诊断，不是预测精度提升。
- 仅替换中间B的专家FC1/FC2 GEMM成本：真反向减少600.985479ms（上述1104.672ms的54.40%）；重计算单独减少229.807311ms（20.80%）；两者一起减少830.792790ms（75.21%）。诊断剩余1F1B误差约2.09%。
- 九类排他性时间的联合顺序平均归因（Shapley）把FC分配为838.719851ms（75.92%）。这不是更改75.21%的直接替换结果；两种口径分别保留。
- 当前支持“源专家成本复用偏高是主要已定位因素”，不支持“已证明专家耗时随PP稳定呈两头大中间小”。模型使用32卡PP1模板，不是256卡两头插值。相同PP1的源/目标专家输入量及kernel次数也不同。
- 真反向FC1/FC2计算权重梯度和输入梯度；前向重计算重新生成激活。梯度产生不是优化器更新；两种FC成本都包含在上述75.21%中。

## 验证边界

仅iter60代表rank（源rank8，目标stage×16）的有效B分项替换与外层DAG调度；PP1另有完整八卡专家输入形状核验。尚非全EP8内部节点替换，不是因果物理占比或跨迭代泛化证明。设备未覆盖区间不等于纯等待，CP kernel不等于纯传输，EP关联kernel不等于全部网络服务成本。其他算子不再继续细化，遵循用户停止该分析的要求。
