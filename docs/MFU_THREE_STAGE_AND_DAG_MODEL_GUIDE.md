# 三阶段 MFU 模型与基于计算图的 MFU 模型说明

## 1. 一句话说明

三阶段模型回答的是：**一轮训练主要由哪些工作组成，各阶段分别花了多少时间**。

基于计算图的 MFU 模型回答的是：**这些工作在不同卡上按照什么先后关系执行，哪些可以重叠，哪些必须等待，最终一轮训练到底需要多长时间**。

两者不是两个互相替代的模型，而是同一个训练过程的两个观察层次：

```text
三阶段视角：便于汇总和解释
        ↓
计算图视角：负责还原真实执行顺序和总时间
        ↓
用最终一轮训练时间计算 MFU
```

当前工程使用计算图作为核心执行模型，同时保留前向、反向和优化器三阶段分类，便于统计和对外说明。

## 2. MFU 是什么

MFU 用于衡量训练过程中 GPU 计算能力被有效利用的程度，可以简单理解为：

```text
MFU = 一轮训练实际需要的计算量
      ÷
      （GPU数量 × 单卡峰值算力 × 一轮训练时间）
```

在模型结构、GPU 数量和单卡峰值算力固定时：

- 一轮训练时间越短，MFU 越高；
- 一轮训练时间越长，MFU 越低；
- 计算、通信和等待都会影响一轮训练时间，因此都会间接影响 MFU。

MFU 模型的核心任务不是单独预测某一次通信，而是正确得到完整一轮训练的结束时间。

## 3. 什么是三阶段模型

一轮训练可以从业务上分成三个主要阶段：

### 3.1 前向阶段

模型读取输入，逐层计算中间结果并生成最终输出。

在流水并行训练中，前向计算从前面的流水阶段逐步传递到后面的流水阶段：

```text
PP0 → PP1 → PP2 → … → PP15
```

### 3.2 反向阶段

根据训练结果反向计算梯度，其中可以包含激活重计算。

反向传播方向与前向相反：

```text
PP15 → PP14 → PP13 → … → PP0
```

### 3.3 优化器阶段

各张卡交换和汇总梯度、准备参数，并执行参数更新。当前案例中的 DP 和 Expert-DP ReduceScatter、AllGather 等通信属于这一阶段。

### 3.4 三阶段模型适合做什么

三阶段划分适合：

- 汇总前向、反向和优化器各自占用的时间；
- 对比不同训练任务在哪个阶段更慢；
- 快速形成报告和性能概览；
- 作为初步性能估算或校准框架。

最简单的三阶段估算可能写成：

```text
一轮训练时间 ≈ 前向时间 + 反向时间 + 优化器时间
```

但在大规模流水并行训练中，这个加法通常不够准确，因为三个阶段内部存在大量并行、重叠和等待。

## 4. 为什么三阶段汇总还不够

当前 256 卡任务使用 16 个流水阶段，但每轮只有 4 个 microbatch，不存在很长的稳定流水区间。不同流水阶段承担的模型层数和工作量也不完全相同。

因此会出现：

- PP0 已经开始工作时，PP15 还没有收到第一个前向输入；
- PP15 可以较早开始反向，但 PP0 必须等待反向结果逐级传回来；
- 有些卡已经进入优化器通信，另一些卡仍在完成反向计算；
- 一段通信可能与其他卡的计算同时发生，因此不会全部增加到最终训练时间；
- 同样增加 10 毫秒通信，有时完全被等待空档隐藏，有时会直接拖慢整轮训练。

如果只取某一个流水阶段作为代表，或者把三个阶段的平均时间直接相加，就无法准确回答上述问题。

## 5. 什么是基于计算图的 MFU 模型

计算图把一轮训练拆成许多带有先后关系的小任务。

### 5.1 节点表示“要做的事情”

例如：

- 某张卡上的第 2 个 microbatch 前向计算；
- 某张卡上的第 1 个 microbatch 反向计算；
- PP13 向 PP14 发送前向结果；
- PP15 向 PP14 发送反向结果；
- 一组卡执行梯度汇总；
- 一组卡执行参数收集；
- 软件发起、同步和完成处理。

每个节点都有自己的执行时间。

### 5.2 连线表示“必须先完成什么”

例如：

```text
PP13 前向计算完成
    → 把结果发送给 PP14
    → PP14 收到结果
    → PP14 才能开始对应的前向计算
```

反向过程则是：

```text
PP15 反向计算完成
    → 把梯度发送给 PP14
    → PP14 收到梯度
    → PP14 才能继续对应的反向计算
```

优化器通信也有类似依赖：只有参与通信的卡都准备好相应数据后，通信才能完成并推动后续任务。

### 5.3 模型自动计算等待和重叠

一个任务的开始时间由它所有前置任务中最晚完成的那个决定：

```text
任务开始时间 = 所有前置任务完成时间的最大值
任务结束时间 = 任务开始时间 + 本任务执行时间
```

这样，等待时间不需要人为指定，也不需要为每个流水阶段填写一个平均“空档”。它会由真实依赖关系自然产生。

没有依赖关系的任务可以同时运行；存在依赖关系的任务必须等待。最终决定一轮训练结束时间的最长依赖链，就是需要重点优化的路径。

## 6. 一个简化例子

假设只有三个流水阶段和两个 microbatch：

```text
前向：
PP0/F0 → PP1/F0 → PP2/F0
PP0/F1 → PP1/F1 → PP2/F1

反向：
PP2/B0 → PP1/B0 → PP0/B0
PP2/B1 → PP1/B1 → PP0/B1

优化器：
各卡反向数据准备完成 → 梯度汇总 → 参数收集 → 参数更新
```

PP0 不需要等待 PP2 完成全部前向后才处理下一个 microbatch；同样，PP2 开始反向时，其他位置仍可能存在前向计算。计算图会同时保留这些局部先后关系和可以并行的部分。

所以，完整训练时间不是所有节点时间的总和，而是从训练开始到最后一个必要任务结束的时间。

## 7. 当前模型如何建立

当前 256 卡模型的主要步骤是：

1. 将每张卡的实测前向和反向记录转换成计算节点。
2. 按每张卡真实的 1F1B 执行顺序连接本地节点。
3. 根据 PP send/recv 连接相邻流水阶段。
4. 将优化器中的梯度汇总和参数收集接到对应反向计算之后。
5. 根据每张卡真正准备好数据的时间，计算一组通信何时能够结束。
6. 将网络传输时间与软件处理、同步等待分开处理。
7. 从训练起点重新计算所有节点，得到完整一轮训练时间。
8. 使用固定的一轮训练计算量、GPU 数量和峰值算力计算 MFU。

从三阶段角度看，这些节点仍然可以归类为：

```text
前向节点
反向节点（包含重计算）
优化器节点
```

区别在于，计算图不再假设三个阶段是整齐、连续和完全串行的。

## 8. OISA 网络仿真在模型中的作用

OISA 只负责回答网络部分的问题：在给定硬件网络、通信量、参与卡和各卡到达时间后，数据传输需要多久。

它不负责：

- 前向和反向计算；
- CPU 与训练框架调度；
- PP 阶段之间的训练依赖；
- 软件同步与完成处理；
- 一段通信是否被其他计算时间隐藏；
- 完整一轮训练什么时候结束。

因此当前模型采用：

```text
网络传输时间：由 OISA 提供
软件处理和同步开销：由当前硬件集群实测校准
等待、重叠和最终完成时间：由计算图统一计算
```

当前已接入九类主要通信。实验也验证，如果只使用网络仿真时间、删除软件处理和同步部分，完整一轮训练会被低估约 27.7%。

## 9. 三阶段模型与计算图模型的关系

| 对比项 | 三阶段视角 | 计算图视角 |
| --- | --- | --- |
| 观察粒度 | 前向、反向、优化器 | 每张卡、每个 microbatch、每次计算和通信 |
| 主要用途 | 汇总、对比、报告 | 还原执行过程、计算总时间、定位瓶颈 |
| 等待处理 | 容易被合并进阶段平均值 | 由前后依赖自动产生 |
| 通信重叠 | 通常只能整体估算 | 根据时间和依赖逐项计算 |
| 不同流水阶段差异 | 容易被平均掉 | 每个阶段分别保留 |
| 最终 MFU | 根据阶段总时间估算 | 根据完整训练结束时间计算 |

可以把两者的关系概括为：

> 三阶段告诉我们“时间花在哪一类工作上”，计算图告诉我们“这些工作如何共同决定最终时间”。

## 10. 当前结果与精度口径

当前模型对应：

```text
256 GPU
PP16 / CP2 / DP8 / EP8
4 microbatch
iteration 55
```

当前校准回放结果：

| 指标 | 实测 | 模型回放 | 相对误差 |
| --- | ---: | ---: | ---: |
| 一轮训练时间 | 21638.095 ms | 21616.236 ms | -0.101% |
| 固定计算量 MFU | 4.4065% | 4.4107% | +0.095% |

这个结果应描述为：

> 自研计算图 MFU 模型在当前 256 卡实测配置上的校准回放误差为 0.1%。

不能描述为：

> 模型对任意卡数和训练配置的预测精度达到 99.9%。

原因是当前计算节点时间、软件处理和同步开销仍来自同一硬件集群的实测校准。只有在未参与校准的 16 卡、224 卡或其他配置上完成验证后，才能给出跨配置预测精度。

此外，MFU 误差与一轮训练时间误差不是两次独立验证。计算量固定时，MFU 由一轮训练时间推导得到。

## 11. 当前模型能够回答什么

当前模型可以回答：

- 一轮训练中前向、反向和优化器分别占用多少时间；
- 不同 PP 阶段为什么有不同的开始和结束时间；
- 某张卡为什么在等待；
- 某一段通信变慢后是否会影响最终训练时间；
- 哪些通信变化被已有等待时间隐藏；
- 一轮训练时间变化后 MFU 如何变化；
- 当前 256 卡实测流程能否被一致地重新还原。

当前还不能直接保证：

- 换成其他卡数后仍保持 0.1% 误差；
- 换成不同 PP、DP、CP、EP 策略后无需重新校准；
- 只靠一个通信量样本就能准确预测任意通信规模；
- 软件栈和同步开销在不同硬件集群上保持不变。

## 12. 推荐的对外说明

### 简短版本

> 我们先把一轮训练分成前向、反向和优化器三个阶段，再进一步将每张卡上的计算、通信和等待关系构造成完整计算图。模型不是简单累加三个阶段的平均时间，而是按照真实执行顺序计算不同卡之间的并行、重叠和等待，最终得到一轮训练时间并计算 MFU。当前在 256 卡实测配置上的校准回放误差约为 0.1%。

### 强调网络仿真作用的版本

> 网络仿真只提供卡间数据传输时间，软件处理和同步开销由实测数据校准，通信是否影响最终训练时间则由完整计算图判断。这种方法避免把所有通信时间直接相加，也避免仅依靠网络仿真低估端到端训练时间。
