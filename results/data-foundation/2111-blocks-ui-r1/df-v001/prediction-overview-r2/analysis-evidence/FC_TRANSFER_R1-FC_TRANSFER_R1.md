## 精确方法及重要限制

替换对象为关联GEMM kernel的设备活动并集，不替换CPU耗时、不替换整个算子包络。仅改中间B的有效成本：

`B候选 = B冻结 + Σ(目标FC_GEMM并集 − 源FC_GEMM并集)`。

F、PP、首尾B及全部外层依赖边保持不变；B内部其他成本、等待残余在此分项记账中固定。重新进行外层DAG的max依赖调度，不把所有B差值直接加到整轮。

这是**代表rank分项成本的外层DAG诊断**，不是完整EP8内部节点重调度。它假设GEMM活动差能加性迁移到有效B成本；尚未验证八卡内部隐藏并发、通信重叠和关键路径切换。因此75.21%为此诊断口径的解释比例，不能宣布已证明真实物理原因占比。专家GEMM差异可能来自实际token量、非空专家数量、实现或执行效率，不能单称“计算变快”。

所有缺失设备关联均先检查。PP7出现输入第一维为0且20个本地专家token计数全0的调用，允许记录零GEMM并保留CPU和其他成本；非空输入无设备则失败，禁止默认为0。重计算/真反向FC身份按配对顺序推断，尚未逐权重ID证明。
