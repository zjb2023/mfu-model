通信成本放哪里？

CP.start = max(ready[rA], ready[rB])
CP.end = CP.start + t_CP(消息档位)
wait[r] = CP.start − ready[r]

等待由依赖算出来，不再额外拟合一笔同步时长。若保留软件处理开销，必须从CP和本地工作中明确划出，避免重复。

只有确认需要CP输出的计算才接在CP后面；与它无关的工作应走旁路。旁路位置需要后续GPU依赖证据，不在示意图里猜。

为什么是四对，而不是八卡一起等？

CP组：[8,9] [10,11] [12,13] [14,15]。每次CP只约束对应两rank，不添加全8卡CP屏障。

EP组：[8,9,10,11,12,13,14,15]。橙色尾块保留dispatch、专家计算、combine及其处理；跨8卡关系尚未展开，不能将各rank橙块理解为独立计算。

最少保留哪些参数？

参数含义当前状态
C[r,u,0..3]第u单元、每次CP前的本地工作；排除独立CP通信设备归属已有；可迁移成本及就绪边界待标定
t_CP384、t_CP256两rank All-to-All，BF16每rank输入384/256 MiB两类候选共享成本；不能直接把kernel包络当纯服务时间
M[r,u]最后一次CP后的剩余本地工作＋EP融合路径暂保留，不能称为纯计算；不再另加EP网络耗时
等待各rank到达差异和已有资源依赖由DAG推导，不作为自由补差参数

节点数不等于自由参数数：先保留每rank观测，验证一致性后再共享C/M模板。CP也先验证同消息量的不同调用是否能共用参数。

替换规则与验收

旧 F → 新子图的入口与出口，不是“旧F ＋ 4次CP”。整个F按4个单元连接，保留末端处理；EP不拆就不额外计费。
