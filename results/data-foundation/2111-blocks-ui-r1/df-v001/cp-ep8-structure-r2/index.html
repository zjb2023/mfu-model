独立准备，Dispatch 内部汇合，Combine 简化统一出口

蓝色是各 rank 本地工作；绿色是时序支持的 notify 同步点；橙色虚线框是模型近似。图宽不表示耗时。

本次只更新结构表达，不改预测结果。实际数据（payload）传输起止仍未确认：不能把全部传输都放到 notify 后面，也不能将 notify 跨度直接当纯通信成本。

点击模块查看成本边界和证据口径。

Dispatch：不是入口处全员 barrier

各 rank 完成本地计算与路由后，可独立推进 Dispatch 内部准备。notify 的组级汇合来自时序证据，不是额外增加一个通信前屏障。

“本rank分发完成”只是后续专家工作依赖的接口；通知、数据传输和后处理如何重叠，仍待识别。

Combine：用最晚完成收束

统一出口 = max(各 rank 合并完成时刻)。实测出口并非完全一致，本版暂忽略小幅完成差异，便于最简建模；不是已证实的严格 barrier。

这也不等于整层结束，右侧仍保留本层后续工作。通信与专家成本尚未校准，不把旧 M 包络再加一次。

证据：32卡 iter60 / PP1 / F0 / 8个rank / 4层；当前图只画一个单元。所有成本保持未填写，本次不新增精度结论。
