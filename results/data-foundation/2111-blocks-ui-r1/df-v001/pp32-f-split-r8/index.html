明确的通信接口

CP：4个二rank组，每组16次，合计64个匹配操作。BF16输入张量元素数为201326592或134217728；这是每rank输入量，不是链路线上字节量。

EP：8rank组，4次dispatch＋4次combine，共8个融合操作。框架明确含路由布局、重排、通信及同步，不能当成8个已测得纯服务时间的All-to-All。

通信实例目前按组、调用序号和规模匹配；缺少全局通信序列号，匹配状态保留条件性。

接入后端前的门槛

计算片段成本、通信service、就绪依赖必须分开。当前已识别的CP通信不再混算入本地kernel；EP融合块仍需拆解。

框架支持dispatch→专家→combine身份；GPU跨stream等待边尚未闭合。不能先硬加全rank屏障再宣称还原了实测。
