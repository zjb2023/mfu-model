如何接回 F 内部

左侧每个紫色框折叠该层的 4 次 CP 及穿插的本地处理，不是一个额外计费节点。展开时沿用 CP384 / CP256 接口与各 rank 的真实前驱。

准备节点 Pᵣ 保留 CP 后、Dispatch 前的本地工作；不能把这一段从旧 M 块中漏掉。右侧输出再接本层后续工作或下一层，不直接等同整个 F 完成。

成本与等待只算一次

Dispatch / Combine 各为一个共享通信操作，不能在 8 个 rank 上串加 8 次。专家节点 Eᵣ 独立计成本，候选输入为固定 trace 成本，或 a + b × recvᵣ。

只有分离掉到达等待后，通信成本才能用于这张全员就绪图。不能把旧 M 包络、通信包络和 DAG 等待叠加收费。min_recv + recv差值 是另一种整体包络模型，不与这套逐 rank 等待重复使用。

简化规则：先把依赖说清楚

Dispatch 开始 = max(P₈…P₁₅ 完成)
Eᵣ 开始 = Dispatch 完成
Combine 开始 = max(E₈…E₁₅ 完成)

上述共享开始/完成边界是粗粒度近似。真实通信可能分批推进，各 rank 返回时刻可能不同；本图不声称已证明严格全局屏障。框架融合操作中的打包、拷贝、解包等工作也必须在校准时明确归属。
