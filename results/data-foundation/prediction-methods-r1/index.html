32 → 256 卡：各方法预测误差总览

版本定义：旧版＝DeepEP；新版＝普通 MCCL AlltoAll。“旧／新”描述采集所用的 EP 实现版本，不表示只替换通信耗时；具体计算、通信成本替换范围见下表。

同一批 256 卡实测，比较源成本怎么换、预测偏多少。绿色 C = 旧版 DeepEP 32卡 iter60 基线 + 新版 MCCL AlltoAll 32卡 iter155–200 的中间 F/B 专家计算成本；不是旧 iter80 基线。

先看来源与继承关系

“旧60 / 旧80”均指旧32卡 DeepEP 采集的 iter60 / iter80；“新155–200”指新32卡普通 MCCL AlltoAll 采集的 iter155、160、…、200，共10轮按成本项取均值。它们都是源数据，不是256卡目标 iter。

A → B：旧60的1F1B源成本全换为旧80。
A → C → D → E → G：从旧60开始逐项迁移新155–200成本，G另将EP区域收缩为完整包络。
F：新155–200全量成本重建条件图，独立候选，不是E的下一步。

方法编号 A–G 仅用于区分候选；“F前向 / B反向”仍表示训练阶段，两者不要混淆。

① 统一评价口径

预测区间：rank0 首个 F 关联 GPU 活动开始 → 最后 B 关联 GPU 活动完成，包含 1F1B 填充与排空。不含 Profiler 启动、末尾 RS／优化器／AG；不是整轮 MFU 误差。

全 20 轮：iter5–100，每 5 轮一个；末尾 4 轮：85、90、95、100。每个候选用一套固定源成本预测，因此预测时长是一条水平线；随目标实测变化的是误差。

有符号误差 =（预测 − 实测）/ 实测；正数为高估。平均绝对相对误差（MAPE）先取绝对值再平均；标准差采用总体标准差，单位为百分点（pp）。目标历史数据已见，不称盲测。

如何解读当前结果

旧80与新源混合候选在末尾4轮上更接近目标，但不能因此宣称全区间预测更准。红版存在已发现的 gap 建模问题；完整 EP 包络实验则把新 AlltoAll 的实测包络迁移给 DeepEP 目标，两者都不能直接证明“纯通信差异造成多少误差”。

绿色专家更新包含 F 前向 FC1 → 激活/门控 → FC2，以及 B 中的前向重计算与 FC2梯度 → 激活/门控反向 → FC1梯度。不是只改两次 GEMM，也没有把完整 AlltoAll 包络与专家成本重复相加。

新源为普通 MCCL AlltoAll，旧32卡及256卡目标为 DeepEP/ACE。实现、工作量与本地处理差异必须区分；当前候选均有边界，不能仅按表中数字选择为正式最优模型。
